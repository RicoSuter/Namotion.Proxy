# Property journal correctness candidate

Base: `801f7c47`; branch `codex/pr494-property-journal-v3`. Prerequisite: incoming-occurrence removal commit `2a27b7a8` (locally `c2975a19`), which removes the last child/property occurrence without executing key equality. Independent graph-oracle test commit `40043663` is included as `34642160`. No original tests were modified. This commit is the correctness stage; journal hot-path specialization is separate.

The baseline is a desired occurrence sequence before recursive attachment finishes. Nested reconciliation now starts from a property-scoped journal of occurrences actually installed, so retaining an unpublished child adds its missing edge and replacing a partially published collection drains only existing edges. Incoming additions/removals update the journal immediately after the ownership mutation, before descent. Owner identity and baseline revision stop superseded continuations. Seeding creates empty installed journals alongside its desired baselines; release snapshots those installed occurrences. Nested completion refreshes the journal's order and indices for a possible further nested write.

The journal uses pooled records and reusable array-backed entry storage. Each child has a last-entry pointer, while a doubly linked sequence preserves occurrence order. Add/remove are expected O(1), with reference equality and no user key equality. Initialization/copy/completion are O(affected-property occurrences). There is no whole-graph scan, retry loop, or linear active-depth membership lookup. Dictionary operations assume ordinary expected hash-table costs. The existing reachability algorithm and its baseline scans are unchanged. Initial pool/capacity growth allocates; warmed capacities are retained per thread. An interrupted operation retains at most one partial journal per affected property/ownership epoch until a successful reconciliation or owner release clears it. The candidate does not yet specialize single occurrences or defer materialization to actual reentry.

Scope limits: this is evidence for the tested mutation paths, not a general proof for arbitrary side-effecting enumerables. Release and reachability still enumerate settled baselines, which can invoke user code. A structural getter that throws before its own baseline is read may leave that subject partially seeded until release; recovery of an already retained descendant's failed seed is not changed by this journal.
