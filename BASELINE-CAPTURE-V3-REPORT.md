# Persistent baseline capture candidate

Branch `codex/pr494-baseline-capture-v3`, based on root `8563be06`, with scalar reconciliation `98690f46` (local `1ac7626f`), metadata-only unowned admission `d2fa5336` (local `25028bec`), and independent capture acceptance `c633afd7` (local `b48711a7`). No benchmark was run.

A baseline now stores its committed raw value, revision and immutable captured collection occurrences. Null and direct-subject values need no occurrence array; empty collections need none either. Collection values retain one array copied from the occurrences already captured by seeding or reconciliation. Reachability checks subject reference identity in that captured desired sequence. Release copies the active journal's installed occurrences when present, otherwise the committed capture. Reconciliation copies its old side from the baseline, and internal failed-seed recovery uses captured desired occurrences too. Explicit setters retain their normal new-value capture behavior, including same-reference retry when a partial journal exists. The raw value remains available for the existing consumer callback contract.

Arrays are owned by the GC and never mutated or recycled. An enclosing operation can safely retain a snapshot across a nested write replacing or removing that baseline. The baseline dictionary entry grows by one reference; each nonempty collection capture allocates an array with one 16-byte occurrence per entry plus its array header on the target 64-bit runtime. Null/direct-subject values add no per-baseline heap object or array. Copy and membership remain O(affected-property occurrences), with reference equality only; no user key equality, whole-context sweep, or retry loop is introduced. The snapshot replaces repeated old-value/release scans, including their enumerator and boxed-index costs, so the net allocation/CPU result needs measurement rather than inference from the new array alone.

The obsolete live-value `StructuralValueScanner.Contains` implementation was removed. Production delta for capture: **81 added / 157 removed lines, net -76**, across five files including the new 27-line `PropertyBaseline`. Scalar specialization and unowned-admission simplification are separate prerequisite commits and excluded from that count.

Verification uses `dotnet test src/Namotion.Interceptor.Tracking.Tests --no-restore --filter 'Category!=Integration' -m:1 -p:UseSharedCompilation=false`. Final result: **852 passed / 1 failed / 853 total**, recorded in `baseline-capture-v3-final.trx` and `/private/tmp/pr494-baseline-capture-final.log`. The one failure is the independently confirmed Registry object-typed duplicate-index projection defect in `CommittedOccurrenceCaptureTests.WhenReplacingACommittedEnumerable_ThenOldOccurrencesDoNotRequireAnotherRead(replacementKind: 2)`: ownership reports retained child indices `[0,2]`, while Registry retains `[0,1]`. The root task assigned that fix separately. The capture write itself succeeds without re-reading the armed old enumerable.

Before capture, all three local replacement/release/reachability probes failed. The six independent acceptance cases were run against the exact restored baseline and all six failed, with capture five now passing and one reaching the separate Registry assertion above. An internal recovery probe also failed with the original `ResumeFailedSeed` call and passes with captured desired recovery. Existing ordinary, callback, self-writing getter, journal, scalar, failure and ownership-epoch tests pass.

One old test intentionally required old-baseline re-enumeration. Its behavioral assertion remains: a nested write after the terminal but before baseline commit must defeat the older continuation. Its trigger now uses the newly stored enumerable, guarded so discovery is benign and capture performs the nested write. Separate capture tests assert the old committed enumerable is not read again. No test was skipped or removed.

The guarantee covers ownership graph reads, not arbitrary consumer callbacks. Registry and third-party `RefreshCollectionProperty` handlers still receive the original raw value and may enumerate it at the queued callback boundary. The new internal recovery probe uses lifecycle tracking to isolate graph recovery from that separate consumer contract. Failed getter operations retain the documented partial-seed/retry/detach behavior; this change does not promise strong rollback for arbitrary user failures.
